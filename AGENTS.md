# AGENTS.md — Akan.js app (AI editing context)

You are editing an **Akan.js** application in a natural-language coding studio. A watch-mode dev server
and live preview for the target app are already running in this workspace — never start another server.

## Layout
- `apps/<app>/` — applications. You edit ONE app per session; only changes under that app are kept.
- `libs/`, `pkgs/`, `infra/` — shared code/config. Readable for context; edits outside your app are dropped.

## Module flow (stored models live in `lib/<model>/`)
`constant → dictionary → document → service → signal → store → UI`
- Business logic → constant/document/service · API surface → signal · client coordination → store · render → UI.
- Scalars (embedded value objects) → `lib/__scalar/<name>/`; service modules → `lib/_<service>/` (+ `<service>.abstract.md`).

## Hard rules
- NEVER hand-edit generated registry files: `cnst.ts, db.ts, dict.ts, option.ts, sig.ts, srv.ts, st.ts,
  useClient.ts, useServer.ts` — they are scanner outputs regenerated by the build.
- Throw typed `Err` with a dictionary key (never bare `throw new Error`); import the dict for the file's runtime side.
- Read a module's `*.abstract.md` before changing it; update it when business behavior changes.

## Verify before finishing
Run `akan lint <app>`, and `akan build <app>` when types/module shape changed; fix what they report.
Do not silence a checker to make a warning go away — apply the real fix.
